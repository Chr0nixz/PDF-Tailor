# PDF-Tailor v1.1 任务清单

## 1. 文档目标

这份文档用于把当前代码状态收敛成一份可执行的 `v1.1` 开发清单。

和 [roadmap.md](./roadmap.md) 不同，这里不讨论长期方向，只定义下一版真正要做、要验收、要发版的内容。

当前代码已经具备：

- 本地 PDF 加载、单页裁剪、批量应用、撤销重做
- 模板与偏好持久化
- 导出范围选择、导出进度、取消导出
- 主题切换、中英文切换、Toast 反馈
- Tauri 桌面壳
- 页面重排的基础代码雏形

因此，`v1.1` 不再以“补齐基础功能”为目标，而是聚焦两件事：

1. 增加真正能减少重复操作的新功能
2. 把现有能力打磨成更顺手、更稳定的工作流

## 2. 版本目标

`v1.1` 的目标定义为：

- 让多页文档整理更高效
- 让高频批量操作更少依赖手工重复点击
- 让桌面端使用方式更接近正式工具，而不是浏览器 Demo
- 为后续更复杂的 PDF 页面处理功能打好数据模型基础

## 3. 发布标准

`v1.1` 发布前至少满足以下条件：

- 页面重排后的预览、导出、缩略图、当前页切换行为一致
- 批量规则化操作可覆盖常见文档整理场景
- 大于 100 页的文档不会因缩略图缓存导致明显卡顿或持续内存膨胀
- 桌面端具备原生打开、保存和最近文件入口
- 核心主路径有单测和 E2E 回归

## 4. 优先级划分

### P0

- 页面身份模型整理
- 页面重排正式化

### P1

- 规则化批量应用
- 自动裁边 v1
- 预览与缩略图性能优化
- 桌面端文件工作流补全

### P2

- 文档诊断面板
- 快捷帮助与首次引导

## 5. 任务清单

### 5.1 页面身份模型整理

优先级：`P0`

背景：

当前 `pageIndex` 同时承担“源 PDF 页号”和“当前列表顺序”两个角色。这个设计在单纯裁剪场景下还能工作，但会直接限制页面重排、删页、项目恢复和复杂批量规则继续扩展。

主要问题点：

- [Workspace.tsx](../src/components/Workspace.tsx) 直接用 `pages[currentPageIndex]`
- [selectors.ts](../src/store/selectors.ts) 和 store 中多处逻辑用 `pageIndex` 作为唯一页面身份
- 导出和预览也依赖 `page.pageIndex`

任务内容：

- 在页面模型中拆分“源页标识”和“当前显示顺序”
- 明确 store 内部哪些状态按“源页”存，哪些按“显示顺序”存
- 统一当前页、选中页、裁剪状态、模板应用、导出范围的索引语义

建议涉及模块：

- [index.ts](../src/types/index.ts)
- [usePdfStore.ts](../src/store/usePdfStore.ts)
- [selectors.ts](../src/store/selectors.ts)
- [Workspace.tsx](../src/components/Workspace.tsx)
- [PageSidebar.tsx](../src/components/PageSidebar.tsx)
- [ExportDialog.tsx](../src/components/ExportDialog.tsx)
- [PreviewModal.tsx](../src/components/PreviewModal.tsx)

验收标准：

- 重排页面后，当前页和选中页不会错位
- 某页裁剪状态不会误应用到另一页
- 预览、导出和侧栏顺序一致

### 5.2 页面重排正式化

优先级：`P0`

背景：

当前侧栏已经接入了拖拽排序依赖和基础交互，但还缺少“这是正式能力”的完整收口。

任务内容：

- 补齐拖拽排序后的当前页、选中页、缩略图和导出顺序同步
- 增加拖拽中的视觉反馈和放置目标反馈
- 明确“重排影响导出顺序”的产品提示
- 增加“恢复原始顺序”操作

建议涉及模块：

- [PageSidebar.tsx](../src/components/PageSidebar.tsx)
- [DraggablePageThumbnail.tsx](../src/components/DraggablePageThumbnail.tsx)
- [usePdfStore.ts](../src/store/usePdfStore.ts)
- [pdfOperations.ts](../src/utils/pdfOperations.ts)
- [PreviewModal.tsx](../src/components/PreviewModal.tsx)

验收标准：

- 拖拽排序后，预览顺序和导出顺序保持一致
- 重排后的文档页序在整个会话中稳定
- 至少覆盖“拖拽后导出”和“拖拽后继续裁剪”的 E2E

### 5.3 规则化批量应用

优先级：`P1`

背景：

当前模板和批量操作已经可用，但仍然偏“选中哪些页，就应用到哪些页”。真实文档整理常见的是按规则处理，而不是手工选页。

任务内容：

- 增加模板应用规则：
- 奇数页
- 偶数页
- 同尺寸页
- 同旋转页
- 页码范围
- 每 N 页
- 增加“规则预览”，先告诉用户将影响多少页
- 增加批量操作结果反馈，例如“已应用到 24 页”

建议涉及模块：

- [PropertiesPanel.tsx](../src/components/PropertiesPanel.tsx)
- [PageSidebar.tsx](../src/components/PageSidebar.tsx)
- [usePdfStore.ts](../src/store/usePdfStore.ts)
- 新增 `src/utils/pageSelectionRules.ts`

验收标准：

- 不依赖手工多选，也能完成常见批量整理
- 规则结果可预测，且可撤销
- 不同纸张尺寸混排文档中不会错误应用

### 5.4 自动裁边 v1

优先级：`P1`

背景：

这是最直接节省手工拖框时间的功能，也是当前产品最有辨识度的下一步。

任务内容：

- 基于当前页渲染结果做简单内容边界检测
- 提供“一键自动裁边”
- 提供“自动裁边后统一留白”
- 支持应用到当前页和选中页

实现策略建议：

- 第一版先覆盖黑白、高对比扫描文档
- 算法以稳定性优先，不追求一步到位覆盖所有 PDF
- 自动结果出来后仍允许继续手动微调

建议涉及模块：

- [usePdfRenderer.ts](../src/hooks/usePdfRenderer.ts)
- [PdfPageCanvas.tsx](../src/components/PdfPageCanvas.tsx)
- [PropertiesPanel.tsx](../src/components/PropertiesPanel.tsx)
- 新增 `src/utils/autoCrop.ts`

验收标准：

- 常见扫描件能稳定识别主要内容区域
- 自动裁边结果可手调、可撤销、可批量应用

### 5.5 预览与缩略图性能优化

优先级：`P1`

背景：

当前预览会走完整导出链路，缩略图则长期持有 `dataUrl`。在大文档下，这两点都会变成明显的性能瓶颈。

任务内容：

- 预览改为优先生成当前页，而不是先处理整个文档
- 增加相邻页预热策略
- 为缩略图缓存增加 LRU 或数量上限
- 滚出较远区域后释放不常用缩略图

建议涉及模块：

- [PreviewModal.tsx](../src/components/PreviewModal.tsx)
- [useThumbnails.ts](../src/hooks/useThumbnails.ts)
- [pdfExportWorker.ts](../src/workers/pdfExportWorker.ts)
- [workerTypes.ts](../src/workers/workerTypes.ts)

验收标准：

- 大文档预览首屏等待时间明显降低
- 100 页以上文档滚动侧栏时内存波动可控
- 不破坏现有导出正确性

### 5.6 桌面端文件工作流补全

优先级：`P1`

背景：

现在已经有 Tauri 壳，但打开和保存仍主要沿用浏览器模式。既然已经进入桌面端，就应该补齐原生文件工作流。

任务内容：

- 原生打开 PDF
- 原生保存导出结果
- 记住最近打开目录
- 增加最近文件列表
- 导出完成后提供“打开文件所在目录”

建议涉及模块：

- [tauri.conf.json](../src-tauri/tauri.conf.json)
- `src-tauri/src/`
- [Header.tsx](../src/components/Header.tsx)
- [ExportDialog.tsx](../src/components/ExportDialog.tsx)

验收标准：

- 桌面版可不依赖浏览器下载行为完成完整编辑和导出
- 最近文件入口在重启后仍可用

### 5.7 文档诊断面板

优先级：`P2`

背景：

当前已经能识别旋转页和大文档模式，但提示还比较分散。下一步应把这些信息集中成“问题面板”，帮助用户快速理解为什么某些模式不可用。

任务内容：

- 汇总混合尺寸页、旋转页、无裁剪页、`Redraw` 阻塞页
- 提供跳转到问题页的入口
- 为禁用按钮补充明确原因提示

建议涉及模块：

- [Header.tsx](../src/components/Header.tsx)
- [ExportDialog.tsx](../src/components/ExportDialog.tsx)
- [PreviewModal.tsx](../src/components/PreviewModal.tsx)
- [documentWarnings.ts](../src/utils/documentWarnings.ts)

验收标准：

- 用户无需试错就能知道功能受限原因
- 关键问题都可以一跳定位到对应页面

### 5.8 快捷帮助与首次引导

优先级：`P2`

背景：

当前快捷键和批量能力已经很多，但仍偏“知道的人用得很快，不知道的人基本看不到”。

任务内容：

- 增加快捷键帮助弹层
- 增加首次打开后的操作引导
- 在关键按钮禁用时展示原因和替代路径

建议涉及模块：

- [useKeyboardShortcuts.ts](../src/hooks/useKeyboardShortcuts.ts)
- [DropZone.tsx](../src/components/DropZone.tsx)
- [Header.tsx](../src/components/Header.tsx)
- 新增帮助弹层组件

验收标准：

- 新用户不看 README 也能完成主路径
- 高频快捷键有明确入口可查

## 6. 建议开发顺序

建议按以下顺序推进：

1. 页面身份模型整理
2. 页面重排正式化
3. 规则化批量应用
4. 预览与缩略图性能优化
5. 桌面端文件工作流补全
6. 自动裁边 v1
7. 文档诊断面板
8. 快捷帮助与首次引导

原因：

- 前两项是后续页面级功能的基础
- 中间三项直接提升效率和使用便捷性
- 最后两项属于体验完成度增强，可以在主路径稳定后补齐

## 7. 不纳入 v1.1 的内容

以下内容暂不建议放进 `v1.1`：

- OCR
- 云同步
- 在线协作
- AI 摘要、翻译、问答
- 复杂注释编辑
- 全量 PDF 编辑器式功能扩张

原因：

- 会显著偏离当前产品的核心边界
- 难以复用现有代码积累
- 对当前最关键的“裁剪效率”和“桌面端便捷性”帮助不直接

## 8. 结论

`v1.1` 最值得做的不是继续补零散按钮，而是把“页面整理”和“批量规则化”两条线做完整，再用性能优化和桌面端工作流把它们撑起来。

如果只能先做一项，优先做：

`页面身份模型整理 + 页面重排正式化`

这是后续页面级功能、会话恢复和更复杂批量规则的基础。
